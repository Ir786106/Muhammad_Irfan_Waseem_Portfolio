# Owner deployment notes

1. In Google Cloud Console → APIs & Services → Credentials, edit the Firebase web application's browser key. Under Website restrictions allow https://irfan-portfolio-ae62a.web.app/*, https://irfan-portfolio-ae62a.firebaseapp.com/* and https://ir786106.github.io/* if serving Pages. Keep the Firebase API allowlist required by Auth, token refresh, Firestore and App Check. Test sign-in and review submission on each host. [Firebase API keys](https://firebase.google.com/docs/projects/api-keys)
2. In Firebase Authentication → Sign-in method enable Google. Under Settings → Authorized domains retain the Firebase auth handler and the production hostnames above. Remove obsolete domains after testing. Use the emulator for development.
3. Register a reCAPTCHA Enterprise website key for the production domains, register the web app under Firebase App Check, configure the public site key in the client, initialize App Check before Firestore, and allow the required reCAPTCHA frames and scripts in CSP. First monitor valid requests on both hosts. Then enable enforcement for Firestore. [App Check setup](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider)
4. Review firestore.rules locally with `firebase emulators:exec --only firestore --project demo-portfolio "node tests/firestore.mjs"`. After review deploy with `firebase deploy --only firestore:rules,firestore:indexes --project irfan-portfolio-ae62a`. Wait for the composite index to finish building before releasing the updated client. Check the rules against any other clients sharing this database.
5. In Firestore Console open testimonials, confirm permission to publish and change approved to boolean true on individual reviews. Legacy documents without approved stay private. Ensure a timestamp date exists for ordered queries. Three approved reviews reveal the public section.
6. Firebase Hosting applies the configured response headers. Branch-based GitHub Pages cannot set these custom response headers, including cache policies and frame protection. Review the public Pages artifact separately from Firebase ignores.
7. Run `node tools/package-site.cjs` to generate the static release. Firebase serves `release/site` and rebuilds it in the Hosting predeploy hook. After reviewing rules and confirming the index is ready, publish Hosting with `firebase deploy --only hosting --project irfan-portfolio-ae62a`. For GitHub Pages, extract `release/portfolio.zip` into the configured publishing branch or use the contents of `release/site` as the Pages artifact. Keep index.html at its root.
