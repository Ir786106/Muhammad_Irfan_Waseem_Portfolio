How I approach product development

Practical thinking.
Working software.

Strong software is more than a good-looking screen. These are the four questions I bring to a project.

01 / UNDERSTAND

What is the actual problem?

Map the people, decisions and workflows before writing code.

02 / DESIGN

How should it work?

Define the data, permissions, interface states and failure paths.

03 / BUILD

Does the implementation hold up?

Connect frontend and backend around useful end-to-end flows.

04 / VERIFY

Can someone rely on it?

Test critical actions, check accessibility and document limitations.
